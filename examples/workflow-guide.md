# 可运行的任务恢复与版本审核演示

**为作品集从零编写的通用 Mock 教学演示，不是生产系统源码，不生成真实视频。**
只使用 Python 3 标准库，无网络、模型调用、真实 API、凭证或业务资料。

## 运行

在本目录执行：

```bash
python workflow_demo.py --demo
python -m unittest -v test_workflow_demo.py
```

`--demo` 只在临时目录创建 SQLite，结束后自动清理。它打印任务状态、
版本、模拟结果和 `calls`；正常结束时提交 3 次、查询 2 次，其中 1 次提交结果未知。
两个成功提交分别对应素材版本 1、版本 2，业务键重复请求不会增加任务或调用。

可选 `python workflow_demo.py --db ./my-demo.sqlite3` 仅初始化并查看明确指定的
数据库，不提交任务。`--demo` 与 `--db` 不能同时使用；不会默认在当前目录创建数据库。

## 设计

| 场景 | 演示中的处理 |
| --- | --- |
| 同业务键重复请求 | SQLite 唯一键复用同一任务 |
| 生成完成后重开程序 | 从数据库读取已有结果，不再调用 provider |
| 有远端任务号 | 查询原任务，不重复提交 |
| 人工审核 | 审核必须明确对应当前素材版本 |
| 重做素材 | 版本递增，清空旧素材与审核；旧版本审核被拒绝 |
| 提交响应丢失 | 进入 `needs_attention`，重复推进或重做不会触发重提 |

提交前先保存 `submitting`；若恢复时没有远端任务号，同样转为人工核对。
`MockProvider` 返回模拟字符串，`approve()` 代表外部人员明确批准某个版本。
演示采用单进程串行流程，不包含真实媒体生成、审核界面或完整生产调度器。
