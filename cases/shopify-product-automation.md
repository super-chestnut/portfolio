# 商品资料到 Shopify 草稿的自动化

[返回作品集](../README.md)

我独立开发商品上架工具，将飞书商品资料、图片与变体信息接入 Shopify：整理数据、生成和检查文案、组装商品草稿，再把处理结果返回源表，让运营继续审核和发布。

**业务场景**

批量上架需要在表格、素材目录和店铺后台之间重复切换：补标题和 SEO、找图、填变体与价格、设置标签，再登记商品链接。商品资料持续补充时，还要区分新建商品和已有商品的更新。

我把这些操作拆成可重复执行的处理环节，使用 Shopify 官方接口完成数据传递，将人工注意力留给商品内容与发布审核。

**我的独立职责**

完成需求梳理、商品字段映射、文案规则、图片与变体处理、Shopify 接口集成、结果回写和使用维护。工具提供命令行入口与执行预览，可以按批次处理商品。

**输入 → 处理 → 交付**

| 阶段 | 具体工作 |
| --- | --- |
| 输入 | 飞书商品记录、商品图片、共享素材目录、尺寸与价格资料 |
| 准备 | 映射字段、整理素材，检查商品信息和素材是否具备处理条件 |
| 文案 | 结合商品资料与图片生成标题、SEO 标题和描述，并按规则审校 |
| 建稿 | 组装图片、变体、价格、标签等数据，通过 Shopify 接口创建草稿 |
| 回写 | 返回商品标识、链接和处理结果；后续同步发布相关信息 |

**主要功能**

- **资料与素材整合：** 把源表字段和共享目录中的图片、变体、描述信息组织为商品数据。
- **AI 文案与规则审校：** 按商品名称、颜色和允许的卖点生成内容，检查长度、格式及用词，并缓存生成结果。
- **商品识别与查重：** 除页面标识外，使用规范化商品编码判断已有商品与变体关系。
- **新建与更新分流：** 新商品走完整建稿；已有商品的文案同步走局部更新，减少重复处理媒体。
- **预览与回执：** 支持预览执行计划，按商品记录处理结果，并汇总批次情况。

**三个关键设计**

1. **商品身份独立于标题。** 标题会随文案调整而变化，仅靠标题派生的页面标识不足以识别同一商品。工具引入商品编码归一化与查重环节，处理业务编码的写法差异。
2. **生成内容结合确定性规则。** 模型负责组织文案，程序负责检查长度、必需信息和允许用词；人工选定的字段也可以作为生成依据，让内容更贴近业务规范。
3. **将首次建稿与后续维护拆开。** 图片、变体和价格的完整创建与文案更新有不同的处理范围。区分接口操作，方便后续按具体字段维护商品。

**我可以为你交付什么**

可以从“商品表格到 Shopify 草稿”这一条流程开始，交付字段映射、资料检查、批量建稿和结果回表工具；再按需要扩展 AI 文案、共享素材目录接入、变体与价格规则、已有商品更新。

交付围绕客户自己的商品规则、资料格式与审核方式配置，包含部署和使用说明。
