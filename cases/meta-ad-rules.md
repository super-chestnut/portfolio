# Meta 广告规则监控与自动关停

[返回作品集](../README.md)

我独立开发广告监控工具，依据人工设定的规则全天监控 Meta 广告，在条件满足时实际执行关停，将原本需要反复查看后台、判断和操作的工作交给规则流程处理。

**业务场景**

广告运行期间，运营人员需要持续关注表现，并执行已经约定的处理规则。人工值守会占用时间，也难以在全天保持相同的检查节奏。对于标准明确、适合规则表达的关停条件，可以将数据获取、条件判断和执行动作连接起来。

这项工具围绕人工制定的策略工作：运营确定什么情况下需要关停，系统持续检查并执行对应操作。

**我的独立职责**

从业务需求和规则梳理开始，完成 Meta 广告数据接入、规则判断、持续监控与关停操作的开发交付。工作重点是把人的判断条件变成能够重复执行的程序流程。

**输入 → 处理 → 交付**

| 阶段 | 具体工作 |
| --- | --- |
| 输入 | 需要监控的广告范围，以及人工制定的关停规则 |
| 监控 | 全天获取和检查广告表现与运行状态 |
| 判断 | 将数据与已设定的规则对照，识别满足条件的广告 |
| 执行 | 对命中条件的广告实际提交关停操作 |
| 交付 | 可持续运行的规则监控与执行工具 |

**主要功能模块**

- **规则输入：** 将运营人员确定的处理条件转成程序可使用的规则。
- **广告状态与数据接入：** 为持续检查提供广告表现和当前状态。
- **条件判断：** 对照设定范围和规则，决定是否需要进入关停步骤。
- **关停执行：** 调用广告管理能力执行操作，完成从“看到问题”到“处理广告”的工作链路。

**三个工程难点**

1. **让业务语言变成明确条件。** “表现差”需要进一步落实为指标、比较条件和适用范围。规则表达越清楚，系统行为越容易被运营理解和管理。
2. **统一数据与规则的口径。** 广告指标与统计时间范围密切相关。监控流程需要围绕同一口径获取和判断数据，才能准确执行人工设定的规则。
3. **把持续检查与执行动作组织好。** 全天运行涉及重复检查、广告状态变化和外部接口交互。判断与执行各有职责，需要结合当前状态安排处理流程。

**适合承接的需求**

这类工具适合已经有明确运营规则、希望减少反复检查与后台操作的团队。项目可以从一组规则和限定的广告范围开始，让使用者先理解触发逻辑和执行方式，再决定扩展范围。

**我可以为你交付什么**

可以开发广告规则监控工具，将人工设定的条件接到指定的执行动作；也可以按合作范围增加规则预演、执行记录、通知和管理界面。交付包含规则说明、部署使用与维护方式，让运营能够明确知道工具在什么条件下采取什么操作。

本页介绍个人的规则自动化与平台集成经验，不公开原项目的广告账户、规则参数或投放数据。
